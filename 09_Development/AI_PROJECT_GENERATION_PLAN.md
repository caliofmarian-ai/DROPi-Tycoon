# AI Project Generation Plan

## Purpose

This document defines the process for creating DROPi Tycoon Prototype using AI-assisted development.

The goal is to reduce repetitive manual work while maintaining project quality and control.

---

# Development Model

DROPi Tycoon follows an AI-assisted production model.

The workflow:

```
Project Vision

↓

Documentation

↓

AI Planning

↓

AI Generation

↓

Human Review

↓

Testing

↓

Iteration
```

---

# Generation Objectives

AI assistance should help create:

- Project structure
- Game logic
- GDevelop configuration
- Initial assets organization
- Testing scenarios
- Documentation updates

---

# AI Production Roles

## Architecture Agent

Purpose:

Maintain project consistency.

Responsibilities:

- Verify folder structure
- Check dependencies
- Prevent conflicting designs

---

## Gameplay Implementation Agent

Purpose:

Create gameplay systems.

Responsibilities:

- Scenes
- Objects
- Events
- Variables
- Interactions

---

## GDevelop Specialist Agent

Purpose:

Translate design into GDevelop structures.

Responsibilities:

- Event sheets
- Behaviors
- Scene setup
- Object configuration

---

## Testing Agent

Purpose:

Validate generated systems.

Responsibilities:

- Find errors
- Check gameplay flow
- Verify MVP requirements

---

## Documentation Agent

Purpose:

Maintain project knowledge.

Responsibilities:

- Update MD files
- Record decisions
- Track versions

---

# Generation Process

## Phase 1 — Specification

Input:

Design documents.

Output:

Implementation plan.

---

## Phase 2 — Structure Generation

Create:

- Project folders
- Scenes
- Objects
- Data structures

---

## Phase 3 — System Generation

Implement:

- Movement
- Orders
- Delivery
- Economy
- Progression

---

## Phase 4 — Validation

Check:

- Does the project open?
- Does gameplay work?
- Are systems connected correctly?

---

# Human Control Points

Human approval is required before:

- Adding new gameplay systems
- Changing architecture
- Increasing project scope
- Replacing core mechanics

---

# Prototype Generation Priority

The first generated version focuses only on:

1. Player movement
2. First map
3. Delivery loop
4. Reward system
5. Basic upgrade

---

# Automation Limits

AI should not create unnecessary complexity.

Avoid generating:

- Advanced systems before MVP
- Features without gameplay purpose
- Large asset collections before testing

---

# Version Strategy

Generated versions:

```
Prototype_v0.1

Prototype_v0.2

Prototype_v0.3
```

Each version must have:

- Clear changes
- Testing results
- Documentation update

---

# Success Criteria

The AI-assisted workflow is successful when:

- Development is faster
- Documentation remains consistent
- Manual repetitive work is reduced
- Gameplay quality improves

---

# Canonical Rule

AI generates and assists.

Human direction defines the final game.
