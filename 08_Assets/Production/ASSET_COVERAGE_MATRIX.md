## Purpose

This matrix prevents the asset program from becoming a small collection of attractive illustrations that cannot support the actual game. It defines the major visual-equipment domains required by the living economic/logistics world and gives each domain a production target and runtime rule.

Counts are library targets, not a promise that every variant is loaded simultaneously. The active runtime must use reuse, caching, culling, level-of-detail and bounded active-area principles.

## Mandatory Variety Dimensions

### Humans

At mature scale, library multiplication must cover combinations of:

- materially different faces;
- skin tones;
- hair type/color/style;
- age presentation;
- body/silhouette variation;
- clothing families;
- profession/equipment;
- recurring identity continuity;
- role-appropriate pose and animation.

### Buildings

Variants must change meaningful structure, including some combination of:

- footprint;
- height/floor count;
- roof form;
- facade material;
- window rhythm;
- entrance/loading geometry;
- signage/awning;
- service yard/parking/loading arrangement;
- regional architectural language;
- economic function.

### Nature

Variety must be species- and environment-driven rather than palette-only. Include size/age/form changes, seasonal states when implemented, cultivated vs wild vegetation and biome/regional compatibility.

### Products

The same economic product may need multiple physical logistics forms:

- visible unit/product;
- retail pack;
- carton/parcel;
- crate/tote/sack;
- pallet/bulk form;
- refrigerated/protective/special case;
- containerized form where appropriate.

## City Archetype Minimum Set

The world library must support at least these materially distinct families:

1. European classic;
2. East-European mixed historic/postwar/modern;
3. modern metropolitan/business;
4. industrial/manufacturing;
5. river/port city;
6. maritime/coastal city;
7. agricultural/rural regional center;
8. high-tech/innovation city.

Long-term expansion may add Mediterranean, mountain, northern/cold-climate, desert/arid, tropical and other regional families while preserving the same global rendering language.

## Load/Performance Rule

This matrix is a **library coverage** requirement, not a simultaneous-render requirement.

The active game should load/use only relevant district, role, product, vehicle and infrastructure families for the current bounded simulation context. Large-scale variety is achieved through governed content selection, not by keeping thousands of textures resident at once.

## Completion Definition

The asset program is not considered equipped merely because the repository contains thousands of files. Coverage is meaningful only when:

- required world/economy/logistics concepts have visual families;
- diversity is material rather than duplicated;
- source/provenance/state are traceable;
- production-ready derivatives use real runtime contracts;
- player-visible adoption preserves Android performance;
- the world visibly communicates what people, companies and infrastructure do and what goods are moving through it.
