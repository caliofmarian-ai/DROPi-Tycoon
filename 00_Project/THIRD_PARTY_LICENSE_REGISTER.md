## 1. Purpose

This register is the legal/release companion to the asset and world-data governance system.

It records, for material third-party or externally governed asset/data/software families:

- source/provider;
- exact material/version where known;
- license or governing terms;
- commercial-use status;
- modification permission;
- redistribution/embedding implications;
- attribution/notice requirements;
- current provenance evidence;
- release status and required action.

Technical owner approval, visual approval and source reproducibility are not substitutes for legal permission. Conversely, a permissive license does not remove the need to preserve provenance and required notices.

No material enters a commercial runtime merely because it is available online, generated by a tool, or described as free.

## 7. Real-world brand / trade dress policy

Default rule: **fictionalize private commercial brands.**

Permitted real-world identity without separate brand license may include factual geographic references where source/data rights allow, but geographic factual use does not authorize private trademarks or trade dress.

Do not ship without explicit review:

- real company logos;
- copied packaging;
- branded storefront signs;
- branded uniforms;
- real courier/company vehicle liveries;
- trademark-shaped icons used as partnership indicators;
- real advertising creative;
- celebrity likeness/name merchandising use;
- copied screenshots or marketing art from third parties.

`08_Assets/Production/Manifests/BATCH_001_WORLD_FOUNDATION_MANIFEST.md` already instructs that product/cargo art be generic fictional game art rather than copied real-world brand packaging. This register upgrades that principle to a commercial IP gate.

## 10. Icons / reference imagery

Icons generated within the approved asset system require the same generated-art provenance as other art.

External icon packs/reference imagery require their own entries. Reference material must not be treated as a production license merely because it is stored under `Approved_References` or was useful for visual direction.

For every external reference intended to influence a final asset materially, record:

- source URL/provider;
- author/rightsholder where known;
- allowed use as reference/input;
- whether generative-tool input is permitted by the source license/terms;
- whether the final output is intended to reproduce protected elements.

**Approved visual direction is not approval to copy a third party.**

## 11. Generated-art provenance schema

Future source/asset manifests should add a legal provenance object/table with at least:

| Field | Requirement |
|---|---|
| `assetId` | Stable source or runtime ID |
| `sourceFamilyId` | Link to approved source family |
| `sourceHash` | SHA-256 or equivalent of source binary |
| `provider` | Generation/asset provider |
| `toolModel` | Tool/model family/version where available |
| `generatedAt` | Date/time or batch date |
| `governingTermsRef` | Provider terms/license evidence applicable at generation/import time |
| `accountCommercialStatus` | Whether commercial use was permitted by the plan/account terms |
| `promptRef` | Prompt/project instruction or batch manifest reference |
| `inputRefs` | All user/project/external input/reference images and their provenance |
| `realPersonOrBrand` | `none`, or explicit reviewed record |
| `humanEdits` | Material human authoring/editing steps |
| `derivativeOf` | Parent asset IDs |
| `runtimeHash` | Hash of shipped derivative |
| `attribution` | Required release attribution or `none` with basis |
| `reviewer` | Compliance/asset reviewer |
| `reviewDate` | Decision date |
| `releaseStatus` | cleared/conditional/blocked |

This schema is a factual record, not an automatic legal conclusion about copyright protectability.
