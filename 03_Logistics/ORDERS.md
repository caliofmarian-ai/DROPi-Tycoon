# Order System

## Purpose

This document defines the order generation and management system of DROPi Tycoon.

Orders are the connection point between customers, logistics operations, and company revenue.

Every delivery begins with an order.

---

# Order Philosophy

Orders should represent real business opportunities.

The player should evaluate:

- Is this order profitable?
- Do I have enough capacity?
- Can I complete it on time?
- Is it worth using my resources?

Orders are not just tasks.

They are strategic decisions.

# Prototype v0.1 Canonical Order State Machine

This document owns Order lifecycle semantics for Prototype v0.1.

All implementation documents must align with this definition.

## Canonical States

| State | Technical Value | Semantic Meaning |
|---|---|---|
| Created | `Created` | Order generated by the system. Not yet visible to the player. |
| Available | `Available` | Order visible to the player and ready for acceptance. |
| Accepted | `Accepted` | Player accepted the order. Traveling to pickup location. |
| PickedUp | `PickedUp` | Package collected. Player in transit to destination. |
| Completed | `Completed` | Package delivered successfully. Order closed. Reward applied. |
| Failed | `Failed` | Order could not be completed. Reputation affected. Order closed. |

## Allowed Transitions

| Source State | Target State |
|---|---|
| Created | Available |
| Available | Accepted |
| Accepted | PickedUp |
| PickedUp | Completed |
| PickedUp | Failed |

Initial state: `Created`

Happy path: `Created → Available → Accepted → PickedUp → Completed`

Failure path: `PickedUp → Failed`

## Terminal States

- `Completed` — no outbound transitions
- `Failed` — no outbound transitions

## Note on Full-Game Lifecycle

The narrative Order Lifecycle section above describes the full-game business process vision.

States such as `Assigned`, `InTransit`, and `Cancelled` belong to future versions and are NOT part of the Prototype v0.1 state machine.

For exact stored technical values, see `09_Development/GAME_DATA_STRUCTURE.md`.

# Order Types

## Individual Orders

Created by regular customers.

Characteristics:

- Smaller packages
- Shorter distances
- Immediate demand

Purpose:

Provide early-game activity.

---

## Business Orders

Created by companies.

Characteristics:

- Higher volume
- More predictable demand
- Longer relationships

Purpose:

Provide stable revenue.

---

## Contract Orders

Special agreements between the company and organizations.

Characteristics:

- Specific requirements
- Higher rewards
- Reputation impact

Purpose:

Create long-term strategic opportunities.

---

# Order Attributes

Every order contains important information.

---

## Pickup Location

Where the package is collected.

Examples:

- Customer home
- Restaurant
- Store
- Warehouse

---

## Delivery Location

The destination of the package.

---

## Package Type

Defines handling requirements.

Examples:

- Normal package
- Food
- Medical
- Fragile item

---

## Priority Level

Defines urgency.

Levels:

Low

Normal

High

Emergency

Higher priority increases reward but creates more pressure.

---

## Time Requirement

Some orders have deadlines.

Late deliveries affect:

- Reputation
- Customer satisfaction
- Future opportunities

---

## Reward

The financial value received after successful completion.

Reward depends on:

- Distance
- Package type
- Priority
- Customer type
- Company reputation

# Order Generation

Orders are generated based on:

- Population
- Business density
- Time
- Location
- Market demand
- Company reputation

# Order Availability

Orders may be:

- Available publicly
- Assigned through contracts
- Generated from partnerships

# Order Management

Players can:

- Accept orders
- Reject orders
- Prioritize orders
- Assign resources

Poor management creates delays and losses.

---

# Failed Orders

Orders may fail because of:

- Late delivery
- Vehicle problems
- Lack of resources
- Cancellation

Failures affect company performance.
